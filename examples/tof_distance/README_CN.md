# ToF 实时测距示例

在 480 × 480 屏幕上分别显示左右两侧测距数据。默认使用 **VL53L4CDV0DH/1**
（VL53L4CD），同时兼容 **VL53L0CXV0DH/1**（VL53L0X）。每个插槽按芯片 ID
自动选择对应驱动，支持两侧使用不同的受支持型号。
可连接一块或两块 ToF 子板，EEPROM 描述必须有效，Board Type 为 `0x10`。
必要时使用 `module_eeprom_programmer` 写入描述。

## 功能概览

| 功能 | 说明 |
|---|---|
| 单／双侧实时测距 | 支持仅左侧、仅右侧或双侧接入；双侧保持开启、依次测量，独立显示距离与状态 |
| 芯片型号自动识别 | 复位后读取芯片 ID，自动选择 VL53L4CD 或 VL53L0X 的初始化和读取步骤 |
| EEPROM 自动识别 | 根据有效的 ToF 类型描述发现子板，未插入时显示等待提示 |
| 自动分配地址 | 上电关闭两侧 XSHUT，识别后依次启动，左侧分配 `0x30`、右侧分配 `0x31`，复位后重新配置 |
| 左右分屏仪表 | 卡片与插槽对应，显示毫米距离、地址、状态、信号与环境光计数率，以及距离刻度条 |
| 双向挥手识别 | 优先按近场进入／离开顺序识别，前方空旷、两侧均显示 -- 时也能待机；有效背景下保留相对距离路径 |
| 方向动画反馈 | 底部显示手势文字，12 段流水灯沿识别方向运动，动画独立于测距任务运行 |
| 快速采样与方向平衡 | 20 ms 单侧测量预算、交替采样顺序、采样时间及门限越过时间估算，减少漏检和方向偏差 |
| 分侧偏移补偿 | 按型号和插槽独立配置：VL53L4CD 默认 0 mm，旧 VL53L0X 保留 −37 mm 设置；不是自动校准 |
| 异常与重连处理 | 某侧拔出或通信异常后独立清理、重新识别；无效测距清除旧数据，不直接当作拔出 |
| 调试与测试 | 保留限频距离、手势、启动总线扫描及异常日志；采样率和有效率信息使用 Debug，并提供主机算法测试 |

### 快速体验

1. 插入一块或两块已写入有效 EEPROM 描述的 ToF 子板，按下文编译并烧录。
2. 查看对应卡片：出现有效距离表示该侧已开始测量；单侧也能测距，但不能识别左右挥手。
3. 使用手势功能时，连接两侧传感器并让感应区域保持空闲，等待底部显示 `READY - WAVE LEFT OR RIGHT`。前方空旷、两侧均显示 `--` 时也能待机，无需有效背景距离。
4. 手在默认 30 cm 范围内从左侧传感器前移向右侧，然后移出两侧感应区域，应显示 `SWIPE RIGHT`，灯条向右运动；反向则显示 `SWIPE LEFT`，灯条向左运动。
5. 等待冷却及检测器重新准备后再做下一次动作。方向按主板左右插槽定义，不随观察者站位自动翻转。

本示例只显示和记录手势结果，不会据此控制其他设备，也没有触屏交互、历史数据存储或自动校准功能。

## 传感器型号与自动切换

| 硬件角色 | 完整订货号 | 芯片 ID | 初始化与读取 |
|---|---|---|---|
| 默认 | **VL53L4CDV0DH/1** | 16 位寄存器 `0x010F` = `0xEBAA` | ST ULD 初始化和 VHV，20 ms 连续测距；等待数据就绪、读取结果、清除中断 |
| 兼容 | **VL53L0CXV0DH/1** | 8 位寄存器 `0xC0` = `0xEE` | PAL 初始化和参考校准，20 ms 单次测距，保留信号／Sigma 有效性检查 |

复位后先检查 VL53L0X 的型号寄存器，否则以 16 位地址读取 VL53L4CD 的 ID。
未知型号返回 `ESP_ERR_NOT_SUPPORTED`。两个型号出厂地址都为 `0x29`，EEPROM 都使用
ToF 类型，因此扫描到地址或读取到子板描述后仍要确认芯片 ID。重新连接后重新识别，
更换受支持型号无需手动切换驱动或重新编译。

应用统一使用 `mosaico_tof_open()`、`mosaico_tof_read()`、`mosaico_tof_close()`，
地址分配、测量预算和偏移设置也通过组件的通用接口分发到对应型号。

## 硬件与地址分配

本示例专用于 ToF 子板，会在 EEPROM 识别前控制两侧的 XSHUT 引脚。
运行期间请勿在这两个插槽连接其他类型子板，以免影响其同位置引脚。
引脚映射使用 BSP，在指定主板上为：

| 插槽 | XSHUT | 传感器地址（7 位） |
|---|---|---|
| 左侧 | GPIO48 | 0x30 |
| 右侧 | GPIO47 | 0x31 |

应用启动时，先将两侧 XSHUT 拉低，再初始化显示和 EEPROM 发现服务。
某侧识别到有效 ToF 描述并取得插槽使用权后，仅开启该侧传感器，
通过默认地址 `0x29` 识别芯片、初始化，再分配为该侧地址。两侧初始化依次执行：
另一侧要么保持关断，要么已改址并保持开启。改址前检查目标地址冲突，
改址后探测新地址确认通信。EEPROM 地址不变。

两侧初始化完成后都保持开启，测量预算均为 20 ms。单任务依次读取就绪插槽，
并交替改变先读的一侧。VL53L0X 每次触发单次测量，VL53L4CD 连续运行并等待下一组
就绪数据。采样循环让出一个 RTOS tick（`CONFIG_FREERTOS_HZ=1000` 时约 1 ms）。
实际成对采样率取决于型号、数据就绪时刻及 I²C 开销，可通过 Debug 统计查看。
不使用 INT。初始化或重试期间，另一侧的刷新间隔可能暂时变长。

总线和模块管理器初始化后，无论有无模块、描述是否有效，均扫描一次非保留的
7 位地址 `0x08`～`0x77`，打印所有应答地址和设备数。此时两侧 XSHUT 均为低电平，
因此通常只发现 EEPROM 和其他已上电器件，ToF 传感器尚未启动。初始化时会另行验证
分配后的 `0x30`／`0x31` 地址。

拔出或通信异常时，只清除对应侧显示，将该侧 XSHUT 保持为低电平，
销毁句柄并释放插槽。清理失败会保留使用权并定时重试，不使用阻塞式重试循环，
另一侧仍会继续被处理。重新插入时重新初始化和分配地址，不主动复位正常工作的另一侧。
无效测距本身不触发重连；仅状态码 0 的距离视为有效。

地址不永久保存，复位后需要重新分配。传感器意外掉电复位后，
程序在检测到测量失败时进入恢复流程。软件不能保证物理热插拔时的触点接通顺序。

## 界面与日志

顶部标题为 `ESP-MOSAICO TOF MODULE`，左右并排的两张卡片分别显示对应侧的数据：

- 插槽、识别到的型号和传感器地址。
- 约 72 px 的距离数值，以及醒目的 28 px `mm` 单位。
- 测量或连接状态。
- 返回信号强度、环境光计数率，单位 MCPS，不是照度 lux。
- 0～2000 mm 水平刻度条；有效读数超出刻度时仍显示实际数值，刻度条停在最大位置。

测量无效时清除旧距离并显示状态码。屏幕触摸未启用，亮度为 80%。
采样任务每 100 ms 提交一次数据快照，手势事件立即提交。LVGL 任务通过 50 ms 定时器
绘制最新快照并消费待显示事件。提交过程不等待显示锁，因此屏幕绘制或传输变慢不会
阻塞测距采样。中间的显示数值可以合并，手势算法仍处理每组采样；后续状态更新不会
覆盖尚未显示的手势事件。
各侧有效数据日志限为每秒一次，包含插槽名称、距离、信号和环境光计数率。
Debug 级别每五秒输出 `Dual sampling: ... pairs/s` 和 `Sample validity`，用于查看
成对采样率和有效率。Info 级别保留初始化、改址、异常、手势和各侧每秒一次的距离日志；
原始芯片 ID 和常规采样统计归入 Debug。

排查漏识别时，可启用 `ToF Distance Demo → Log gesture sampling diagnostics every five
seconds`（`CONFIG_TOF_GESTURE_DIAGNOSTICS`，默认关闭）。每五秒三行 Info 日志报告
实际成对采样率、循环及界面提交最大耗时、各侧有效／总样本数、最后状态码和读取平均／
最大耗时。每秒一次的距离日志经过限频，不能用来判断实际采样率。开启诊断不会改变
测量预算或手势门限。

在同一组双 VL53L4CD、20 ms 测量预算下，原同步界面调用使采样仅为 3.6～3.7 组／秒，
界面阻塞曾达到 278 ms。异步提交界面状态后实测约 51～52 组／秒，提交耗时不超过 1 ms。
这是该硬件场景的实测值，不保证所有场景均达到同样速度。两种受支持型号的状态码 2
均表示信号不足／没有可信目标，近场算法将其作为区域空闲的证据，但忽略其距离，卡片
仍显示 `--`。其他无效状态仍视为未知，可能阻止待机；传感器有效性检查不变。

## 左右挥手识别

两个数据卡片下方增加手势识别区域，显示手势文字及 12 段流水灯条：

- 左侧先完成距离变化、右侧随后完成：显示 `SWIPE RIGHT`，灯条从左往右运动。
- 右侧先完成距离变化、左侧随后完成：显示 `SWIPE LEFT`，灯条从右往左运动。
- 结果保持约 2.5 秒，流水灯由 LVGL 定时器独立驱动，不依赖测距任务刷新。

近场识别不需要背景。两侧在线且区域空闲 80 ms 后即可待机：有效距离不超过 300 mm
视为手进入；有效距离达到 360 mm 或状态码为 2 时视为离开。中间 60 mm 区间保持
先前状态以减少抖动，不把无效距离伪造为远距离。每侧脉冲至少需要两帧近场数据并持续
25 ms，两侧进入时间至少相差 25 ms；完成顺序需一致，允许不足 25 ms 的采样抖动。
只同时遮挡两侧不会产生方向手势。

近场检测器尚未待机时，原来的相对距离算法仍可学习稳定的有效背景，包括近场范围内的
固定背景。近场待机后由它处理整个动作，避免把经过的手重新学习成背景。两种路径共享
800 ms 冷却，避免同一动作重复触发。完全发生在两次采样之间的动作仍可能漏检。

底部提示含义：

| 提示 | 含义 |
|---|---|
| `WAIT FOR TWO SENSORS` | 子板缺失或数据未知／故障；状态码 2 本身不会阻止空旷待机 |
| `HOLD STILL / CLEAR SENSORS` | 清空两侧感应区，或保持有效背景稳定，等待重新准备 |
| `READY - WAVE LEFT OR RIGHT` | 可以尝试左右挥手 |
| `SWIPE RIGHT` / `SWIPE LEFT` | 最近识别出的动作；显示期间不代表一直处于可触发状态 |

相对距离补充算法的规则：

- 默认距离变化达到 **60 mm** 才开始记录脉冲，回到距基线 **30 mm** 内认为脉冲完成。
- 支持“变大再变小”，也支持手靠近时的“变小再恢复”；两侧变化方向须相同，开始和结束顺序须一致。
- 从第一个脉冲开始到两个脉冲结束须在 **1500 ms** 内；开始时间至少相差 25 ms，单个脉冲至少持续 25 ms，识别后冷却 800 ms。
- 同时变化或顺序不明确不判定方向。缺少子板或数据过期（超过 500 ms）会清除未完成的手势；
  对仍连接的传感器，允许最多 80 ms 的无效样本间隔，只跳过这些样本，不使用其距离。
  无效间隔超限后取消当前手势并重新学习基线。
- 识别、拒绝或超时后重新学习基线。没有有效背景只会限制此补充路径，近场路径仍可使用。
- 每轮交替左右采样顺序，以各侧测量起止时间的中点作为采样时间，并在相邻数据间线性估算越过门限的时刻，不再统一使用整轮结束时间。这用于减小顺序读取带来的方向偏差，不等于硬件同步采样。
- 起始顺序明确、结束时间相同时仍可识别；起始同时或顺序矛盾仍拒绝，同时检查每侧数据是否过期。
- 每五秒的 Debug `Sample validity: left=... right=...` 日志可比较两侧有效读数数量；若差异明显，应检查安装朝向、背景和遮挡情况。

可在 `menuconfig → ToF Distance Demo` 中调整：

- `Gesture distance excursion threshold (mm)`：变化幅度门限。
- `Gesture completion window (ms)`：手势完成时间窗口。

近场范围通过 `Near-field hand detection distance (mm)` 设置，对应
`CONFIG_TOF_GESTURE_NEAR_MM`（默认 300，范围 100～1000 mm），退出距离自动加 60 mm。
范围过大可能将附近桌面／家具算作近场目标，应按安装位置验证。

相对距离和时间窗口对应配置项为 `CONFIG_TOF_GESTURE_THRESHOLD_MM`（默认 60，范围 20～500 mm）和
`CONFIG_TOF_GESTURE_WINDOW_MS`（默认 1500，范围 500～3000 ms）。回落门限自动取幅度门限的一半；25 ms 时间条件和共享的 800 ms 冷却定义在算法／应用中，不是菜单配置项。

降低幅度门限会更灵敏，也更容易误触发。手势功能不改变地址、校准补偿或 INT 使用方式。
缩短测量预算可能增加噪声或弱信号下的无效读数，需实机复测距离和手势效果。
60 mm 幅度门限、回落滞回、先后顺序检查和冷却仍保持有效。

## 编译与烧录

使用支持 ESP32-S31 的 ESP-IDF 6.2 或更新版本，激活环境后从仓库根目录执行：

```bash
cd examples/tof_distance
idf.py build
idf.py -p PORT flash monitor
```

将 `PORT` 替换为实际串口。显示、电源、I²C 总线及插槽映射使用 BSP 接口。
硬件版本支持跟随 BSP（v1.0、v1.2；v1.1 使用 v1.2 映射），新增双侧功能仍需实机验证。

## 分侧距离偏移补偿

在 `idf.py menuconfig → ToF Distance Demo` 中按型号和插槽分别设置：

| 型号 | 左侧配置 | 右侧配置 | 默认值 |
|---|---|---|---|
| VL53L4CD | `CONFIG_TOF_L4CD_LEFT_OFFSET_ADJUST_MM` | `CONFIG_TOF_L4CD_RIGHT_OFFSET_ADJUST_MM` | 0 mm，保留出厂校准 |
| VL53L0X | `CONFIG_TOF_DISTANCE_OFFSET_ADJUST_MM` | `CONFIG_TOF_DISTANCE_RIGHT_OFFSET_ADJUST_MM` | −37 mm，保留旧分支针对特定子板的设置 |

旧 −37 mm 设置来自一块 VL53L0X 子板：实际距离 100 mm 时读数约 137 mm，200 mm 时约
243 mm。该补偿不会自动套用到新的默认 VL53L4CD，也不代表其他 VL53L0X 有相同误差。
配置由识别出的型号和插槽共同选择，请先分别验证每块子板再使用非零补偿。

复位后仅叠加一次补偿，并回读验证；设置为 0 时不写偏移寄存器。保留有符号的
0.25 mm 出厂偏移精度，以及 VL53L4CD 的其他校准寄存器。补偿同时影响屏幕和日志，
存储在固件配置中，不写 EEPROM/NVS。这是手动补偿，不是自动偏移或串扰校准。
请从各颗传感器的光学表面量取已知距离进行验证。

## 验证范围

整合版本已通过 ESP32-S31 编译。原生 LVGL 检查还覆盖显示阻塞时连续提交 10000 次状态、
最新样本合并、调用方数据复制、待显示手势保留、左右独立状态、重连及无效数据显示。UBSan 主机检查覆盖 VL53L4CD 双侧改址和读取、
VL53L0X 接口分发、测量预算、有符号偏移、出厂寄存器保留、另一侧隔离、改址重绑定失败清理及读取失败处理。
双 VL53L4CD 实机已确认：空旷环境下，两侧显示 `-- / NO TARGET` 时可以进入 `READY`，
随后能够触发左右手势，日志也记录到双向事件，采样保持约 51 组／秒。混合型号手势仍需
实机验证；这些观察不是经过统计的识别成功率。

主机回归测试覆盖双向脉冲、两种距离变化方向、重叠脉冲、结束时间相同、抖动、无效数据、超时、冷却、时间戳回绕，以及交替采样下的不同相位。原有模拟相位测试左右各 12/12 通过，新增 50 Hz 下的相位／极性组合为 80/80；
丢帧测试覆盖 60 ms 的短暂缺失及超限后的取消。无背景的不同方向／采样相位组合为 40/40，覆盖时间戳回绕，并验证状态分类、故障、
同时遮挡和单帧尖峰拒绝。这些结果不是实机成功率。

实机验收建议：测试双侧同时上电、仅单侧插入、左右分别拔插和独立地址日志；分别验证距离补偿；在相同路径、速度与背景下各做多次左右挥手，结合 `Sample validity` 和 `Dual sampling` 日志比较效果。物理安装、背景反射和动作速度仍会影响识别。
